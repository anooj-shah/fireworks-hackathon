## Notes
- **This is a gain over its own untrained base, not over the frontier.** No frontier model has been scored yet (no closed-model key as of 14:20).
- Examples: the first three Pop rows of `dev.jsonl` in file order, not cherry-picked (human / base / fine-tuned, SimBench S):
  - `pop-2465` (ESS). Human A17 B49 C14 D14 E6. Base A65 B25 C8 D2 E0 (−50.0). FT A10 B55 C24 D8 E3 (**+49.9**).
  - `pop-6686` (TISP). Human A2 B7 C24 D48 E18. Base A0 B2 C5 D23 E70 (−70.3). FT A1 B1 C1 D20 E77 (**−93.5**, more overconfident on the wrong answer).
  - `pop-5250` (GlobalOpinionQA). Human A26 B38 C27 D10. Base A15 B25 C30 D30 (+33.3). FT A1 B10 C24 D65 (**−55.2**, confidently wrong).
  - So the fine-tune is better on average (63% of questions) but can still spike. Softening its answers toward even (harness idea) might help.
- **Scoring a finished run from a separate process:** `--model-path accounts/<a>/trainingSessions/<ts>/checkpoints/<name>` returned 400 "Invalid serverless training model" for both the short and server-stored names, even with the session `READY`. What works: `train/sample_eval.py --from-checkpoint <account>/<run-id>/step-<final>`. It loads the final DCP checkpoint into a fresh LoRA session (rank 16, alpha 32), saves a sampler snapshot, samples, then closes that session. Only the final step has a DCP checkpoint (`dcp_save_interval=0`), so mid-run sampler checkpoints can't be scored this way.
- Scoring speed is fine at `-c 48`: ~21 requests/s, so all of dev takes ~70 s. The 12.8 s p50 in the 5-row smoke test was warm-up.
